# Agent 邮箱 · 智能体专属邮箱

[首页](../../README.zh-CN.md) · [English](../../scenes/agent-mailbox.md)

**一个只属于 Agent 的邮箱，和你的私人邮箱完全分开：管它收到的验证码和服务通知、其他 Agent 与系统发来的报告、别人写给它的反馈，以及它对外发信用的身份。你的私人邮件它看不见；它要发的信，先给你看，你确认了才发。**

## 你能得到什么

- **一个能写在外面的地址**——注册服务、留给项目用户发反馈、放在产品页上，收到的全是给 Agent 的事，不占用你的私人邮箱。
- **验证码和通知的固定落点**——要 Agent 出面注册、验证、盯状态变化的服务，邮件都落在这里；它自己读了处理，只把要你决定的报给你。
- **Agent 之间的邮路**——别的 Agent 把报告、交接单、结果寄到这里，你的 Agent 收下归档；不同工具、不同厂商也能通。
- **发信先过你这一关**——它起草、你确认、才发出；每天发了多少、收了什么，问起来它说得清。

## 把这段交给 Muse

整段复制给你的 Muse，它照着把专属邮箱建起来，然后陪你跑起来。

```text
帮我给 Agent 建一个专属邮箱，和我的私人邮箱分开。

用我指定的 Agent 邮箱服务申请一个地址（如果还没有），把地址记下来。这个邮箱只给 Agent 用：它不读我的私人邮箱，我的私人邮箱也不接入它。

这个邮箱管四类信：
1. 验证码和服务通知——注册、验证、续费、状态变化，都落在这里。
2. 机器和 Agent 发来的报告——部署结果、任务回执、监控报警。
3. 写给 Agent 的反馈——项目用户、合作方发来的问题和建议。
4. Agent 对外发信——以这个地址发出的回复、通知和交接单。

规则：
1. 发信、回复、转发一律先起草给我看，我确认了才发；服务自带确认流程的，走它的确认流程，不要绕过。
2. 收到的信先分诊：能直接处理掉的（归档、进台账、进档案）就处理，只把要我决定的和异常的报给我；没事不汇报。
3. 验证码只用于它当次正在办的注册或登录，用完不留存、不转发；来路对不上的验证码请求，先问我再用。
4. 这个地址可以公开写出去，但我的私人邮箱、电话等个人信息，不出现在它的签名和它发出的信里。
5. 每天的收发记一笔：收了什么、发了什么、哪些还等我确认，我问起来要能说清。

现在就开始：先把地址建好或确认好，然后问我第一件要用它收的信是什么。
```

## 它怎么运转

- **隔离是默认状态**——Agent 被来路不明的邮件带偏，最多污染这一个箱子，碰不到你的私人邮件和联系人。
- **它是很多场景的进料口**——订阅台账从这里收续费通知，收件箱分诊从这里收机器报告，交接单从这里寄出和接收。箱子本身不产出清单，进料顺了，其他场景才跑得动。
