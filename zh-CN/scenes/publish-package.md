# 发布包 · 一份稿备好几个渠道的版本

[首页](../../README.zh-CN.md) · [English](../../scenes/publish-package.md)

**一个 Muse 把一份已确认的稿子备成多渠道发布包的流程：每个渠道一版——标题、正文、素材、链接都按那个渠道的受众和格式改。没有授权的素材留在清单里，不进包。全部先是草稿，你逐版批了才发；发完，把发布链接记回包里。**

## 你能得到什么

- **一个逐渠道的版本包**——邮件简报一版、社区动态一版、短视频文案一版……每版独立成文，你可以一版一版审、一版一版改，不用从原稿里自己裁。
- **一份素材清单**——每张图、每条链接标清：已确认可用，还是待授权。待授权的只出现在清单里，绝不混进待发版本。
- **一份发布回执**——真正发出去后，哪个渠道、什么时间、公开链接是什么，记回包里；草稿和已发布永远分得清。

## 把这段交给 Muse

整段复制给你的 Muse，它照着把发布包流程建出来，然后陪你跑起来。

```text
帮我把一份已确认的稿子做成多渠道发布包。

起点：一份我确认过的原稿，和我要发的渠道清单。只用原稿里已确认的事实，不要在改写时加新说法。

每个渠道出一版，包含：标题、正文、要用的素材、链接。按渠道的受众和格式改写——字数、语气、结构服从渠道，但事实只来自原稿。

规则：
1. 素材逐个标状态：已授权可用 / 待授权。待授权的留在清单里，不进任何待发版本。
2. 全部版本先是草稿。我逐版确认后，你才可以发；发哪个渠道、什么时候发，听我的。
3. 发布后把回执记回包里：渠道、时间、公开链接。没有回执的，状态保持「草稿」，不要标已发布。

现在就开始：先问我原稿在哪、要发哪几个渠道，再出第一版给我审。
```

## 它怎么运转

- **一份底稿，多个出口**——原稿改一处，各渠道版本跟着重出，不会出现公众号改了、社区版还是旧说法。
- **包就是档案**——发过什么、用的哪版文案、配的哪张图，这个包里全有，下次同主题发布直接接着用。
