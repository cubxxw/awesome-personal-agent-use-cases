# API 密钥台账 · 密钥和额度一处看全

[首页](../../README.zh-CN.md) · [English](../../scenes/api-key-ledger.md)

**一个 Muse 替你管的 API 密钥台账：管你每个平台的订阅档位、每把 key 的额度还剩多少、什么时候到期、key 存在哪。额度它定期实测回写，key 你自己存一处、点一下就能复制，要用哪把喊它一声就读给你。**

## 你能得到什么

- **一张全量表**——订阅和 API key 在同一块板上：每个平台一行，档位、价格、额度总量、已用/剩余、状态、到期日，一眼看全。哪个平台有两把 key，分两行记，不合并。
- **实测的额度，不是猜的**——能用平台自己的 API 查的，它查完把数字和实测日期一起写回；查不到余额的（有的平台根本不给余额接口），明确标「仅控制台可见」，不编数字。
- **死 key 当周就被抓出来**——过期的 token 在每周巡检里现形，不用等你真要用它干活时才发现调用失败；换新 key 走安全录入，不在聊天里贴明文。
- **key 真能取回来**——你把 key 粘进它那一行存好，平时打码显示，点一下复制；在聊天里说「把 Tavily 的 key 给我」，它从板上读出来发你。放进保险库（Secure Vault）的 key 是另一条轨：它能拿着调用，但谁也读不出原值——想能复制，就在板上再存一份。
- **清理决定归你**——每行能标 保留 / 再看看 / 待取消，能只筛「待取消」集中处理；它不会凭一个标记就去退订，动手前逐个跟你确认。

## 把这段交给 Muse

整段复制给你的 Muse，它照着把台账建出来，然后陪你跑起来。

```text
帮我建一个 API 密钥台账，把我各个平台的订阅和 API key 管起来。

先建台账：每个平台一行，记档位、价格、额度总量、已用/剩余（带实测日期）、状态、到期或续费日、key 的名字和存放位置。台账只记这些元数据，永远不写 key 的值；日期查不到的留「待补」，不要猜。

再建一块能打开看的板（Space 或同类页面）：台账内容同步上去，每行带清理标记（保留 / 再看看 / 待取消）和「待清理」筛选，到期日可以在板上直接补填。

规则：
1. 额度能用平台 API 查的就实测查（如用量接口、账户信息接口），把数字和日期一起记；平台不给余额接口的，标「仅控制台可见」，不估、不猜。
2. key 分两条轨存：要你自动调用的，进 Secure Vault，你只能用、读不出原值；我要自己能复制的，我自己粘进板上那一行，打码存、点击复制，你要能从板上读回来给我。
3. 新 key 通过安全录入交付，不在聊天里贴明文；巡检发现 key 过期或失效，当天标红并告诉我换法。
4. 同一个平台有多个账号或多把 key，分行记，永不合并——两把 key 额度对不上，往往是两个账号。
5. 每周巡检一次，并入我已有的周报（如周一晨间简报），不另开打扰渠道；只在三种情况下出声：余额低于我定的线、key 过期或失效、到期日在 30 天内。无事沉默。
6. 清理标记只是我的决定记录，不等于执行：真要退订或删 key，逐个跟我确认了再动手。

现在就开始：先把台账和板建起来，然后把我现有的平台清单逐个录入，第一轮额度能实测的都实测一遍。
```

## 它怎么运转

- **巡检骑在现成的报告上**——额度更新并入周报，不新增一个会响的渠道；板上的数字和台账文件每次巡检后同步刷新。
- **订阅和 key 共用一块板**——订阅那侧的扣款、渠道、重复订阅，订阅台账那篇管得更细；这一篇管的是 key 和额度这一侧。
- **分工写在台账里**——哪把 key 在保险库、哪把在板上、哪把只在本地配置里，台账都写明，下次换人（或换会话）接手不用猜。

## 来源

- **平台官方接口。** TikHub 账户与 key 状态接口：余额、key 名、scopes、到期日一次读回。[TikHub 文档](https://docs.tikhub.io/)
- **平台官方接口。** Tavily 用量接口：按账号返回 plan、已用 credits 和剩余量，两把 key 分属两个账号就是这样查出来的。[Tavily 文档](https://docs.tavily.com/)
- **平台口径。** Exa 不提供余额接口，余额只在控制台账单页可见——台账里这类平台标「仅控制台可见」。[Exa 控制台](https://dashboard.exa.ai/)
