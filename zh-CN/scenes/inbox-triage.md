# 收件箱分诊 · 今天哪几条真得回

[首页](../../README.zh-CN.md) · [English](../../scenes/inbox-triage.md)

**一个 Muse 替你分诊收件箱的晨间清单：把邮箱和消息分成「今天必须回、稍后看、等材料」三堆，管每条的截止时间、谁在等你、还缺什么。要回的先起草，你确认了才发；真正紧急的，才单独打断你。**

## 你能得到什么

- **一份短清单**——今天要回的排在最前，每条写清：谁在等你、等什么、截止几点。新闻信、通知类自动沉到「稍后看」。
- **回复草稿**——要回的消息先有一版草稿等你批。你改了再发，它还会问你一句：这次修改它该学到什么，下次起草就照你的改法来。
- **分级打扰**——普通消息只进清单；只有你定为紧急的那类（比如某几个人、带硬截止的事），才即时提醒你。
- **机器发的信单独一堆**——部署结果、任务报告、监控报警这类由系统和 Agent 发的通知，走 Agent 的专属邮箱，不进你的私人收件箱；分诊时单独成段，只把要你拍板的挑出来给你。

## 把这段交给 Muse

整段复制给你的 Muse，它照着把分诊建出来，然后陪你跑起来。

```text
帮我建一个收件箱分诊，每天早上给我一份清单。

范围：我指定的邮箱和消息来源、最近的日期。按发件人实际提出的事分类，不要按标题猜。

清单分三段：
1. 今天要回——对方在等我回复的，每条写：谁、等什么、截止时间、原消息出处。
2. 稍后看——没有待办的（新闻信、通知、抄送），只列标题。
3. 等材料——读不到附件、信息不齐的，照样列出来，标明缺什么，不要假装看过。

规则：
1. 「今天要回」的每条，先给我一版回复草稿。我确认或改完，才发送；没确认的草稿就留在清单上，不要自己发。
2. 我改了你的草稿，发送前问我一句：这次修改你学到了什么？把答案记下来，以后起草先按我的改法来。
3. 紧急提醒的标准由我定（哪些人、哪类事可以即时打断我）；没定的，一律只进清单。
4. 回复、归档、退订是三个独立动作，各做各的，不要顺手连带。
5. 机器和 Agent 发的通知，只分诊 Agent 专属邮箱里的那一份，私人邮箱不再收这类；这类通知默认进「稍后看」，只有需要我决定的才升到「今天要回」。

现在就开始：先问我接哪个邮箱、从哪天开始分诊，再给我第一份清单看。
```

## 它怎么运转

- **清单是每天的唯一入口**——邮箱再满，你早上只看这一份；看完，该回的回了，剩下的心里有数。
- **草稿越用越像你**——每次你改稿，它学一次；几周后，多数草稿你扫一眼就能发。
- **人和机器分开进**——人找你走私人邮箱，机器找 Agent 走专属邮箱；早上你只看分诊完的一份清单，两个箱子都不用自己翻。
