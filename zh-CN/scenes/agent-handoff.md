# 交接单 · 换个会话，项目还能接着做

[首页](../../README.zh-CN.md) · [English](../../scenes/agent-handoff.md)

**一份 Muse 在收工时留下的交接单：管一个项目跨会话、跨 Agent 的连续性——目标是什么、当前产物在哪、哪些结果已经核过（核到什么范围）、还差什么、下一步是什么、哪些动作要重新授权。新会话只读这一张单子就能接上，不用从头猜。**

## 你能得到什么

- **一张六项交接单**——目标、产物位置、已核结果及范围、未完成事项、下一步、权限边界。每项带出处，接手的人能逐项复核。
- **一步能直接干的下一步**——不是「继续推进」，而是具体到打开哪个文件、核对什么、产出什么；接手方照着就能开工。
- **写清的权限边界**——上一个会话能做的，不等于新会话自动能做：对外发送、写入、发布这类动作，在单子上标明要重新确认。
- **能寄出的交接单**——接手的是另一个 Agent、它有自己的邮箱时，交接单可以直接寄过去：正文是单子，产物做附件。对方收到就能接手，不用和你共用一个会话或同一套工具。

## 把这段交给 Muse

整段复制给你的 Muse，它照着把交接流程建出来，然后陪你跑起来。

```text
每次收工或换会话之前，给我留一份交接单，存到产物旁边。

交接单写六项，每项带出处：
1. 目标——这个项目要做成什么，一句话。
2. 当前产物——最新版本在哪（文件名/链接），哪个是准的。
3. 已核结果——已经核对过什么、核到什么范围（比如「本地预览打开、3 个内部链接可点」），没核的不要写成已核。
4. 未完成事项——还差什么、卡在哪。
5. 下一步——一个具体动作，接手的人照着就能干。
6. 权限边界——哪些动作接手后要重新找我确认（对外发送、发布、写入等）。

规则：
1. 交接单只写接手用得上的，不写过程流水账。
2. 新会话接手时，先只读交接单和它指向的文件，再动手；单子和实际文件对不上的，先报我，不要猜哪个是真的。
3. 换工具、换 Agent 时，访问权限单独确认：交接单跟着走，权限不跟着走。
4. 交接对象是另一个 Agent 且它有专属邮箱时，交接单可以按邮件寄出（正文放单子、产物放附件）；寄出前先给我看，确认才发。收到交接邮件的一方，先核对单子和附件对不对得上，对不上先报我。

现在就开始：先问我哪个项目要交接，拿它写第一份给我看。
```

## 它怎么运转

- **交接单是项目的记忆**——会话会断、Agent 会换，这张单子让「上次做到哪」永远有据可查，中途停下也不丢结果。
- **分工靠它传递**——一个 Agent 出简报、另一个归档，调研交给写稿：交接单就是它们之间唯一的传递格式。
- **邮件是最通用的投递**——不同厂商、不同工具的 Agent 之间没有共享会话时，一封带附件的邮件就能把交接单送到。
