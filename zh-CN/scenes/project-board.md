# 项目看板 · 哪件事卡住了，卡在哪

[首页](../../README.zh-CN.md) · [English](../../scenes/project-board.md)

**一个 Muse 替你维护的项目看板：一个项目一张卡，管它现在什么状态、卡在什么地方、下一步是谁的什么动作。状态只跟着能核对的事件变——草稿写好了不等于发布了，说上线，必须有发布回执。**

## 你能得到什么

- **一张随时能看的看板**——每张卡四件事：状态、阻塞（卡在谁、卡在什么）、一个明确的下一步、这个状态的来源。打开就知道今天该去推哪件。
- **一条状态历史**——每次状态变化都留一行：哪天、因为什么变的。过段时间回看，能讲清一个项目是怎么走到今天的。
- **更新先预览**——它先给更新预览，你确认了才写进看板；同一条事件重复投递，历史里也只记一次。

## 把这段交给 Muse

整段复制给你的 Muse，它照着把看板建出来，然后陪你跑起来。

```text
帮我建一个项目看板，一个项目一张卡。

每张卡记：项目名和编号、当前状态、阻塞（卡在什么、等谁）、下一步（一个动作，负责人明确）、状态来源（哪条消息、哪份回执）。

规则：
1. 状态只根据能核对的事件更新：收到回执、有人确认、文件出现。你的猜测和我的转述不够，先标「待确认」。
2. 「草稿好了」「已提交」「已发布」「已交付」是不同状态，分开记；标已发布/已交付之前，要有发布回执或负责人确认。
3. 更新先给预览，我确认了才保存。同一条事件重复出现，历史里只记一次。
4. 负责人看不出来的，下一步就写「待定负责人」，不要替我指派。

现在就开始：先把看板建起来，然后问我先放哪几个项目、每个项目的状态从哪份材料对起。
```

## 它怎么运转

- **看板是项目的唯一状态源**——晨间行动单、周报都从这里取状态，不再各算各的。
- **共享视图只给必要字段**——要给协作者看时，生成只含对方需要字段的视图，内部备注不外泄。
