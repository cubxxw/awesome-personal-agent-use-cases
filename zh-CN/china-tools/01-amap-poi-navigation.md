# 高德地图 POI 查询与导航入口

**核对日期**: 2026-11-22 (Asia/Singapore)  
**官方文档**: [高德开放平台 MCP Server](https://lbs.amap.com/api/mcp-server/summary)

## 用户需求

"明晚下班后,我要先去取快递,再去一家药店,19:30前到朋友约的地方。帮我比较顺路的走法,把几个点放进高德,出门前提醒我。"

## 具体结果

你会拿到:

1. **POI候选列表**: 避免同名分店混淆
2. **分段路线比较**: "起点→取件点→药店→目的地" 每段估时
3. **手机可打开的入口**: 
   - 专属地图唤端链接 (多个地点一起展示)
   - 导航唤端链接 (单个目的地导航)
   - 打车唤端链接 (打开打车业务入口)
4. **待确认项清单**: 哪些条件需要你核实
5. **(可选) 出门提醒**: 若接日历/任务系统

## 适用环境

### Host要求

✅ **可用**:
- 桌面MCP Host (支持HTTP transport)
- 云端Agent环境 (需要能访问高德API)

⚠️ **限制**:
- 需要Host支持 **Streamable HTTP** transport
- 云端Host需要确认对 `https://mcp.amap.com` 的网络可达性

### OS要求

- Host端: Linux / macOS / Windows (运行MCP Host的环境)
- 手机端: iOS / Android (打开高德App的设备)

### 2. MCP Host配置

#### 方式一: 官方远程服务 (推荐)

**无需安装**, 直接配置endpoint:

```json
{
  "mcpServers": {
    "amap": {
      "transport": {
        "type": "streamableHttp",
        "url": "https://mcp.amap.com/mcp?key=<YOUR_AMAP_API_KEY>"
      }
    }
  }
}
```

**重要**:
- `<YOUR_AMAP_API_KEY>` 替换为你的真实Key
- Key会出现在URL中,注意日志和截图安全
- **不要把真实Key提交到代码仓库**

#### 方式二: 本地Node服务

**前置条件**:
- Node.js >= 22.14.0

**安装**:

```bash
npm install -g @amap/amap-maps-mcp-server
```

**配置** (stdio transport):

```json
{
  "mcpServers": {
    "amap": {
      "command": "amap-maps-mcp",
      "env": {
        "AMAP_API_KEY": "<YOUR_AMAP_API_KEY>"
      }
    }
  }
}
```

**说明**:
- 本地Node包仍需要联网访问高德API,不是离线地图
- 环境变量方式避免Key出现在配置文件中

**SSE服务已下线** (2026-03-17):

| 工具 | 输入 | 返回 | 实际能做的 |

| POI详情 | POI ID | 详情信息 | 核对具体分店,避免同名 ⚠️文档未承诺营业时间覆盖率 |

## 配置步骤

### 步骤1: 获取API Key

1. 访问 https://lbs.amap.com/api/mcp-server/create-project-and-key
2. 登录/注册高德开放平台账号
3. 创建应用,选择"Web服务"
4. 复制生成的API Key

### 步骤2: 配置MCP Host

根据你使用的Host,选择对应配置方式:

**示例 (假设使用支持配置文件的Host)**:

```json
{
  "mcpServers": {
    "amap": {
      "transport": {
        "type": "streamableHttp",
        "url": "https://mcp.amap.com/mcp?key=<YOUR_AMAP_API_KEY>"
      }
    }
  }
}
```

**⚠️ 重要提示**:
- 不同Host的配置方式可能不同
- Muse等产品的具体配置需要查阅对应文档
- 本文档不假设任何Host有"添加MCP"的图形界面

### 步骤3: 验证连接

重启Host后,验证高德MCP是否可用:

```
你: 帮我搜索北京市朝阳区的星巴克

预期: 应该返回POI列表,包含名称、地址、坐标等信息
```

## 最小测试

### 测试1: 关键词搜索

**输入**:

```
搜索"北京市 停车场",返回前3个结果
```

**预期响应字段**:
- `name`: POI名称
- `address`: 地址
- `location`: 经纬度坐标
- `id`: POI唯一标识

**失败识别**:
- 返回错误码 (如 `INVALID_USER_KEY`, `DAILY_QUERY_OVER_LIMIT`)
- 超时无响应
- 返回空列表但未说明原因

### 测试2: 路线规划

**输入** (虚构坐标):

```
驾车路线: 从 116.397428,39.90923 (天安门) 到 116.481488,39.990464 (鸟巢)
```

**预期响应字段**:
- `distance`: 距离(米)
- `duration`: 预计时间(秒)
- `steps`: 分段指引

**失败识别**:
- 起点或终点不在服务范围内
- 路线规划失败但未给出原因

### 测试3: 唤端链接

**输入**:

```
生成导航链接到坐标 116.481488,39.990464
```

**预期响应**:
- 一个可点击的 `amapuri://` 开头的链接

**验证方法**:
1. 复制链接
2. 在安装了高德App的手机上打开
3. 应该跳转到高德App并显示目的地

**失败识别**:
- 链接格式不正确
- 点击无反应
- 跳转到错误的位置

## 完整使用示例

### 场景: 下班顺路办事

**用户输入**:

```
我现在在望京SOHO (坐标: 116.481488,39.990464)
需要依次去:
1. 取件点: 望京快递代收点
2. 药店: 附近的同仁堂或海王星辰
3. 最终目的地: 三里屯 (坐标: 116.447174,39.937676)

帮我:
1. 搜索附近的快递代收点和药店
2. 比较不同顺序的路线
3. 生成最优路线的地图链接
```

**Agent应该做的步骤**:

1. **搜索POI**:
   ```
   周边搜索: 关键词"快递代收", 中心点116.481488,39.990464, 半径2000米
   周边搜索: 关键词"药店", 中心点116.481488,39.990464, 半径2000米
   ```

2. **让用户确认**:
   ```
   找到3个快递代收点:
   A. 望京代收站 (距离500米)
   B. SOHO快递柜 (距离200米)
   C. 社区服务站 (距离800米)
   
   找到5个药店:
   D. 同仁堂望京店 (距离600米)
   E. 海王星辰SOHO店 (距离300米)
   
   请确认:
   - 取件点选择: A/B/C?
   - 药店选择: D/E?
   ```

3. **计算路线** (假设用户选择B和E):
   ```
   驾车路线1: 望京SOHO → B快递柜 → E药店 → 三里屯
   驾车路线2: 望京SOHO → E药店 → B快递柜 → 三里屯
   ```

4. **比较并给出建议**:
   ```
   路线1: 总距离8.2km, 预计23分钟
   路线2: 总距离8.5km, 预计25分钟
   
   建议选择路线1 (更短2分钟)
   
   注意事项:
   - 预计时间未考虑实时路况
   - 药店营业时间需要自行确认
   - 快递取件窗口需要确认
   ```

5. **生成地图链接**:
   ```
   专属地图链接(包含所有途经点): amapuri://...
   
   分段导航:
   - 导航到B快递柜: amapuri://...
   - 导航到E药店: amapuri://...
   - 导航到三里屯: amapuri://...
   ```

**⚠️ 不应该做的**:
- ❌ 直接断言"E药店现在开门"
- ❌ 直接提交打车订单
- ❌ 承诺"按这个路线一定不堵车"
- ❌ 自动把提醒加到用户日历(需要单独授权)

## 重开/持久化

### 定时提醒

**能做到的**:
- 固定时间检查提醒: 需要额外的调度服务
- 日历集成: 需要单独的日历工具权限

**不能假设的**:
- ❌ 桌面聊天窗口关闭后自动在后台运行
- ❌ Muse会在明天自动"醒来"重新计算路线

**正确做法**:

如果需要"出门前30分钟提醒":

1. **方案A - 日历事项** (需要日历工具):
   ```
   创建日历事项:
   - 标题: "出发去三里屯"
   - 时间: 18:30 (假设19:00到达,提前30分钟)
   - 描述: 包含地图链接和路线说明
   - 提醒: 事件开始时
   ```

2. **方案B - 定时任务** (需要调度服务):
   ```
   创建定时任务:
   - 执行时间: 18:30
   - 任务: 重新查询路线并发送通知
   - 通知方式: Bark推送/企业微信/钉钉等
   ```

2. **保存位置**:
   - 云端: 保存到坚果云WebDAV / 飞书文档
   - 本地: 保存到思源笔记 / Obsidian

## 关闭/撤销方法

### 停止使用高德MCP

1. **从Host配置中移除**:
   - 删除 `mcpServers.amap` 配置项
   - 重启Host

2. **吊销API Key** (可选):
   - 登录高德开放平台控制台
   - 找到对应应用
   - 删除或禁用API Key

**副作用**:
- 所有使用该Key的请求立即失败
- 已生成的唤端链接仍然有效(链接不依赖API Key)

### 清理数据

**需要清理的**:
- 配置文件中的API Key
- 日志文件中可能包含的Key和坐标
- 保存的路线记录(如果包含敏感位置)

**不需要清理的**:
- 高德App中的历史记录(由App自己管理)

## 已知限制与注意事项

### 1. 数据准确性

⚠️ **不是实时保证**:
- 营业时间可能不准确
- POI信息可能过时
- 路况预测基于历史数据

✅ **建议做法**:
- 重要事项前人工确认营业时间
- 出发前查看实时路况
- 备选方案(如备用药店)

### 2. App依赖

⚠️ **需要高德App**:
- 唤端链接需要手机安装高德App
- 不能假设所有用户都装了高德

✅ **降级方案**:
- 同时提供经纬度坐标
- 用户可以复制到其他地图App

### 3. 网络与地理限制

⚠️ **可能的问题**:
- 云端Host访问高德API的连通性
- 某些地区的POI覆盖不完整
- 国外地点查询可能失败

✅ **检查方法**:
- 每次使用前先测试简单查询
- 返回错误时检查error code

### 4. 费用与配额

⚠️ **未明确的限制**:
- 官方文档未在所读页面明确免费额度
- 超出配额后的费率待确认
- 商业使用条件待核对

✅ **安全做法**:
- 在控制台查看当前用量
- 设置预算告警
- 不要用于高频自动化任务

## 故障排查

### 问题1: "INVALID_USER_KEY"

**可能原因**:
- Key输入错误
- Key已被删除
- Key类型不是"Web服务"

**解决方法**:
1. 检查配置中的Key是否正确
2. 去控制台确认Key状态
3. 重新生成Key并更新配置

### 问题2: "DAILY_QUERY_OVER_LIMIT"

**可能原因**:
- 超出每日配额
- 短时间内请求过多

**解决方法**:
1. 等待第二天配额刷新
2. 升级套餐(如果可用)
3. 优化请求频率

### 问题3: 唤端链接点击无反应

**可能原因**:
- 手机未安装高德App
- 系统不支持amapuri协议
- 链接格式错误

**解决方法**:
1. 确认高德App已安装
2. 尝试复制链接后在浏览器打开
3. 检查链接格式是否完整

### 问题4: 搜索结果为空

**可能原因**:
- 关键词不匹配
- 坐标超出服务范围
- 该区域POI数据缺失

**解决方法**:
1. 更换搜索关键词
2. 扩大搜索半径
3. 尝试周边其他地点

## 进阶用法

### 与其他工具组合

1. **高德 + 飞书日历**:
   - 从飞书日历获取会议地址
   - 用高德计算出发时间
   - 创建"出发提醒"事项

2. **高德 + 滴答清单**:
   - 识别待办中的地点信息
   - 自动规划顺路办事路线
   - 完成后更新待办状态

3. **高德 + Bark推送**:
   - 定时查询路线
   - 发现拥堵时推送提醒

### 批量查询优化

**不推荐**:
```javascript
// ❌ 循环调用100次POI搜索
for (let i = 0; i < 100; i++) {
  await searchPOI(keywords[i]);
}
```

**推荐**:
```javascript
// ✅ 合并请求、控制并发
const results = await Promise.all(
  keywords.slice(0, 10).map(k => searchPOI(k))
);
```

**原因**:
- 避免触发限流
- 减少API消耗
- 更快获得结果
