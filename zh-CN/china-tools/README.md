## 重要说明

### 什么能写,什么不能写

**✅ 可以写的**:
- 有官方文档或一手实践证据的接入方法
- 明确前置条件、账号要求、费用和配额
- 具体的配置步骤和测试方法
- 明确标注未验证部分和谁需要做什么

**❌ 不能写的**:
- 用京东/点评/12306规则资料冒充工具接入
- 编造 Muse 的"设置-添加MCP"UI
- 把研究私有/逆向API、复制cookies当推荐方案
- 承诺"一键配置"或"全自动"而无具体验证
- 把截图场景当作已接通的工具

### Muse 身份与能力

根据仓库 BUILDER.md 和官方安全说明 (https://security.muse.ai/, 作者 Tarek Sheasha, 2026-09-08):

- **Muse 是**: [Muse from Meta](https://apps.apple.com/us/app/muse-from-meta/id6760173601), 开发者 Meta Platforms, Inc.
- **云端能力**: 使用云端 Linux VM, 具备浏览器、shell、存储和并发任务
- **自定义连接器**: 若服务有API或CLI, Muse可以编写自定义连接器
- **明确无法推定的**: 不能假设有消费者App手填MCP URL的菜单、incoming公网webhook、永不停止的服务器或能操作用户手机

### 地理与网络限制

- 高德官方当前为 Streamable HTTP `https://mcp.amap.com/mcp?key=<KEY>`, SSE已于2026-03-17下线
- 国内模型HTTP兼容不等于Host/模型支持tools
- Muse/云端的请求地理连通性不能预设
- localhost是本机地址,不等于云端或跨设备通用

### 安全与隐私原则

- 配置示例用清楚占位符 `<YOUR_KEY_HERE>`, 绝不放真secret
- 避免裸露有权webhook
- WebDAV公网服务需要明确鉴权
- 手机推送不是已读确认
- 不操作用户真实账号、不发真实通知、不提交订单、不消费

## 如何使用本指南

1. **先选一个实际需求**: 不要一次全装,选一个自己确实会反复遇到的任务
2. **核对前置条件**: 每条路径都明确列出Host、OS、账号、费用等要求
3. **按步骤操作**: 跟随文档中的操作顺序,不跳步
4. **验证结果**: 用文档提供的测试方法验证每一步
5. **理解限制**: 明确知道什么能做、什么不能做

## 文档结构说明

每条完整路径包含:

1. **用户需求** (一句自然的描述)
2. **具体结果展示** (用户会拿到什么)
3. **适用环境** (Host和OS要求)
4. **前置安装** (所有依赖和运行位置)
5. **账号/资格/费用** (明确待核的内容)
6. **安装与版本** (具体步骤和依赖)
7. **官方授权方法** (安全放置密钥)
8. **配置示例** (用占位符的完整配置)
9. **最小测试** (输入、预期响应、失败识别)
10. **重开/持久化** (实际能力说明)
11. **关闭/撤销方法** (副作用说明)

## 贡献指南
