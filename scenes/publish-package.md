## Try it with material you have

Paste the full block below. The input is fictional.

```text
Prepare a review package for a newsletter and a community update. Use the same approved facts but write for each audience. For each version, include headline, text, assets, link and pending checks. Keep any unapproved asset out. Return drafts, no publishing.
A1 | approved text | Shelf labels made it easier to return shared tools.
A2 | internal photo | permission pending

```

## With a connected tool

Start from an approved source draft and a list of channels. Save each version and its asset checklist together. Check platform-specific length and format in the destination. After any approved publication, record the public link or receipt.

## How to check it

Both versions use A1 and A3. The shorter one has a clear point for its readers. A2 is held in both, and sending status stays at draft.

## Decision boundary

Publishing needs your approval of the exact copy, destination and asset rights. Keep the confirmed public URL with the version that was sent.

## How the cases fit together

Content pipelines prepare different assets around the same topic. The itinerary-share example shows the same audience decision outside publishing: give each recipient the information they need. This scenario starts once the core content has been approved.

- Prepare show notes, description and a short announcement from an approved episode.
- Create a short project update and a fuller changelog from the same confirmed release notes.
