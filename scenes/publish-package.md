# Publish package · One draft, every channel's version

[Home](../README.md) · [简体中文](../zh-CN/scenes/publish-package.md)

**A package Muse prepares from one approved draft: a version per channel — title, text, assets and links re-cut for that channel's audience and format. Assets without usage permission stay on the checklist and never enter the package. Everything is a draft until you approve it version by version; once something ships, its public link is recorded back into the package.**

## What you get

- **A per-channel version pack** — one version for the newsletter, one for the community post, one for the short-video caption: each stands on its own, ready for you to review and edit one by one instead of cutting them out of the original yourself.
- **An asset checklist** — every image and link labeled: cleared to use, or awaiting permission. Awaiting-permission assets appear only on the checklist, never inside a version waiting to ship.
- **A publication record** — once a version actually ships, its channel, time and public link are recorded back. Draft and published never blur.

## Give this to Muse

Paste the whole block into your Muse. It builds the package flow, then runs it with you.

```text
Turn one approved draft of mine into a multi-channel publish package.

Starting point: one draft I have approved, and the list of channels I want. Use only facts confirmed in the original — add no new claims while re-cutting.

Each channel gets one version: title, text, the assets it uses, and links. Rewrite for that channel's audience and format — length, tone and structure follow the channel; facts come only from the original.

Rules:
1. Label every asset: cleared to use, or awaiting permission. Awaiting-permission assets stay on the checklist and enter no version.
2. Every version is a draft first. Only after I approve a version may you publish it — which channel, and when, is my call.
3. After publishing, record the receipt in the package: channel, time, public link. Without a receipt, the status stays "draft" — never mark it published.

Start now: ask me where the original is and which channels it goes to, then produce the first version for my review.
```

## How it runs

- **One master, many exits** — change a fact in the original and every channel version regenerates from it, so the newsletter never says what the community post already corrected.
- **The package is the archive** — what shipped, in which wording, with which image: all in one place, ready to reuse for the next piece on the same topic.
