# 个人 Agent 用例库

先选一件最近遇到的事。每个场景都有一份能直接试的样例，也写明怎样核对结果。

[English](README.md) · [怎么搭](zh-CN/BUILDER.md) · [案例来源与筛选](zh-CN/EVIDENCE.md) · [设计](ARCHITECTURE.md) · [贡献](CONTRIBUTING.md)

**先试 [下次扣款前叫我](zh-CN/scenes/renewal-ledger.md)**。拿一组收据和通知做一份续费清单，日期查不到的留待确认。

## 生活

| 场景 | 你会拿到什么 |
| --- | --- |
| [家庭日程板 · 这周谁要去哪](zh-CN/scenes/household-calendar.md) | 一个 Muse 替全家维护的日程板：学校通知、群消息和共享日历合成一张周视图，管每个人的安排、改期、冲突和谁负责接送；有变化先报你确认，再写进日历。 |
| [订阅台账 · 下次扣款前叫我](zh-CN/scenes/renewal-ledger.md) | 一个 Muse 替你记账的订阅台账：管你订了哪些服务、走哪个渠道扣款、多少钱、下次哪天扣、有没有重复订；扣款前提前叫你，续不续你决定。 |
| [Personal CRM · 朋友与联系人](zh-CN/scenes/personal-crm.md) | 一个 Muse 替你维护的联系人库：一人一页，管联系方式、彼此的关系和状态、生日祝福、你答应过的事；见人之前，自动给你一页会前卡。 |
| [维修档案 · 坏了先找上次修过的人](zh-CN/scenes/home-repair.md) | 一个 Muse 替你存的家庭维修档案：管每台设备的型号、上次谁修的、花了多少、保修到哪天；东西坏了，先把上次的师傅和工单找出来给你。 |
| [行程单 · 把预订拼成一张](zh-CN/scenes/trip-brief.md) | 一个 Muse 替你拼的行程单：把散在邮件里的航班、酒店、接送确认拼成一张按当地时间排好的单子，管每段的时间、地点和还没确认的事；发给别人时，再生成一版只含日期地点的简版。 |
| [降价盯梢 · 降到预算再叫我](zh-CN/scenes/price-watch.md) | 一个 Muse 替你盯价的 watch：你定死条件——什么东西、什么规格、含全部费用的总价上限——它定时去查，达标才叫你，没达标不打扰；下单永远你来。 |

## 工作

| 场景 | 你会拿到什么 |
| --- | --- |
| [收件箱分诊 · 今天哪几条真得回](zh-CN/scenes/inbox-triage.md) | 一个 Muse 替你分诊收件箱的晨间清单：把邮箱和消息分成今天必须回、稍后看、等材料三堆，管每条的截止时间、谁在等你、还缺什么；要回的先起草，你确认了才发。 |
| [文件档案柜 · 三个月后找得到那张发票](zh-CN/scenes/file-filing.md) | 一个 Muse 替你归档文件的档案柜：管发票、收据、保修单、合同——原件不动，先建一份能搜的索引，写清哪个商户、哪天、多少钱、原件在哪；疑似重复先标出来。 |
| [会前卡 · 进会议室前看一页](zh-CN/scenes/meeting-prep.md) | 一张 Muse 在会前替你备好的一页卡：管上次确认过的决定、还没定的事、这次该问的问题，每条带出处；提议和承诺分得清，不会把「也许能做」写成答应了。 |
| [会后清单 · 谁答应了什么](zh-CN/scenes/meeting-followups.md) | 一份 Muse 从会议纪要里替你提的会后清单：管这场会定了什么、谁答应了什么、哪天之前交、哪些还没定负责人；你确认后才写进任务系统，之后追到底。 |
| [晨间行动单 · 开工前看真要办的几件事](zh-CN/scenes/daily-plan.md) | 一份 Muse 每天早上替你排好的行动单：一条主线、最多三件事，管每件的开始时间、下一步和卡在哪；等别人的事放进等待区，晚上用同一张单子收尾——办完、顺延，还是放下。 |

## 学习

| 场景 | 你会拿到什么 |
| --- | --- |
| [专题简报 · 只看和这件事有关的更新](zh-CN/scenes/reading-digest.md) | 一份 Muse 按专题替你筛的短简报：你定专题和来源，它每天只挑真正有关的新内容，最多三条，每条带原文和入选理由；没有新内容就报一句「今天没有」，不拿旧闻凑数。 |
| [复习出题 · 用我读过的材料问我](zh-CN/scenes/study-review.md) | 一个 Muse 用你自己的笔记出题的复习教练：只从你读过的材料里出题，一次一道、先不给答案；答完对照原文批注——对了哪、漏了哪、该回看哪一页，没答全的过段时间再问。 |
| [收藏库 · 找回曾经收藏的那一篇](zh-CN/scenes/reading-library.md) | 一个 Muse 替你管收藏的库：文章、视频、帖子存的时候连「为什么存」一起记下，按原始来源去重；以后用大白话问一句，它把原文和你当时的笔记一起找回来。 |
| [证据对照表 · 把结论追到原文](zh-CN/scenes/research-compare.md) | 一张 Muse 为一个问题做的证据对照表：每个说法一行，写清测到了什么、在什么条件下测的、原文在哪一段；材料没说的标「没说」，条件对不上的不硬排优劣。 |

## 创作与开发

| 场景 | 你会拿到什么 |
| --- | --- |
| [初稿工坊 · 把零散笔记做成能改的初稿](zh-CN/scenes/draft-from-notes.md) | 一个 Muse 把你的零散笔记做成初稿的工坊：只用你给的素材，每个事实都能回到某条笔记；没说的数字、没授权的引用不替你编，单独列成待补清单给你。 |
| [项目看板 · 哪件事卡住了，卡在哪](zh-CN/scenes/project-board.md) | 一个 Muse 替你维护的项目看板：一个项目一张卡，管它现在什么状态、卡在什么地方、下一步是谁的什么动作；状态只跟着能核对的事件变，说上线必须有回执。 |
| [发布包 · 一份稿备好几个渠道的版本](zh-CN/scenes/publish-package.md) | 一个 Muse 把一份已确认的稿子备成多渠道发布包的流程：每个渠道一版，按受众和格式改；没授权的素材留在清单里不进包，全部草稿先行，你逐版批了才发。 |
| [交接单 · 换个会话，项目还能接着做](zh-CN/scenes/agent-handoff.md) | 一份 Muse 在收工时留下的交接单：管项目跨会话、跨 Agent 的连续性——目标、当前产物在哪、哪些结果已经核过、还差什么、下一步是什么、哪些动作要重新授权。 |
